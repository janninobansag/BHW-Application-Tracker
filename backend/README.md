# BHW Render API

This is the Node/Express API deployed to Render. It uses MongoDB Atlas and serves the existing Next.js frontend through `/api/*` routes.

## Local run

Use Node.js 22.13 or newer. Set `MONGODB_URI`, then run `npm install`, `npm run dev` from this directory. The API listens on port `10000` by default. Configure `RENDER_API_URL=http://localhost:10000` in the frontend project while developing.

## Render environment

`render.yaml` configures the service with this directory as its root. Set these Render variables:

- `MONGODB_URI`: Atlas connection string for the BHW database.
- `MONGODB_DATABASE`: database name, normally `bhw`.
- `SESSION_SECRET`: generated by the Render blueprint and used to HMAC session-token hashes.
- `FRONTEND_ORIGIN`: exact Vercel site origin, such as `https://your-site.vercel.app`.
- `ADMIN_SETUP_TOKEN`: a long, one-time secret for first Admin setup. Remove it after setup.

Render builds with `npm ci && npm run build`, starts with `npm start`, and checks `/health`.

## Move existing D1 data

Do the data import before exposing the new frontend. The export includes users (including existing Argon2id password hashes), account states, barangays, puroks, assignments, children, and settings. It omits D1 sessions and login attempts. The importer also invalidates MongoDB sessions for migrated users.

From the `backend` directory, set a Cloudflare API token with D1 read access, the account ID, and the D1 database ID, then run:

```powershell
$env:CLOUDFLARE_API_TOKEN = "..."
$env:CLOUDFLARE_ACCOUNT_ID = "..."
$env:CLOUDFLARE_D1_DATABASE_ID = "..."
npm run export:d1
```

The private snapshot defaults to `../outputs/d1-export.json`, which is ignored by Git. It contains password hashes; keep it private and remove it after successful import. To store it elsewhere, set `D1_EXPORT_PATH` to the same path for both commands.

Set `MONGODB_URI` to the new, empty Atlas database and run:

```powershell
npm run import:d1-json
```

The importer refuses a populated target database. It can resume an interrupted import from the same snapshot, and it never copies old session tokens. A different snapshot needs a fresh MongoDB database.

## Vercel frontend

Import the repository into Vercel with the repository root as the project root. Configure `RENDER_API_URL` to the Render service's HTTPS origin (no `/api` suffix), for example `https://bhw-api.onrender.com`, for every Vercel environment. The Next.js rewrite forwards `/api/backend/*` downloads to Render; server actions use the same URL directly. Set `FRONTEND_ORIGIN` on Render to the exact production Vercel origin.

After importing D1, sign in with the migrated Admin account. If the database has no Admin, use `/setup` with `ADMIN_SETUP_TOKEN`. Remove that token from Render after the Admin password is set.

No service is deployed or published by these source changes. Keep the current site and D1 available until the new API and frontend have been configured and verified.
